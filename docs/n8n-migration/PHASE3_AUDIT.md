# Phase 3 Audit

Audit date: 2026-06-30.

## Existing Call Graph

`pipeline_service.run_request()` remains the old public entrypoint. In Phase 3 it now executes:

1. `run_intake_stage(context)`
2. `run_normalize_stage(context)`
3. `run_calculate_stage(context)`
4. `run_reconcile_stage(context)`
5. `run_report_stage(context)`

The financial formulas remain in the original modules:

- `field_mapper.map_billing_sheet`
- `normalizer.load_billing_rows`
- `income_calc.compute_income`
- `fee_calc.compute_hq_fee`
- `fee_calc.compute_team_delivery_cost`
- `fee_calc.compute_bill_crowd_order_counts`
- `crowd_cost_contract.build_crowd_cost_result`
- `reconcile.run_all_checks`
- `report.generate_report`

## Stage Boundaries

| Stage | Main Inputs | Main Outputs |
| --- | --- | --- |
| intake | run request, city profile, input files | `input-manifest.json`, `run-context.json` |
| normalize | input manifest, billing Excel files | `normalized-data/normalized.sqlite`, `normalization-manifest.json`, `schema-report.json` |
| calculate | normalized SQLite, crowd cost workbook, city config | `calculation-result.json`, `calculation-manifest.json` |
| reconcile | calculation result, normalized metadata | `stage-reconciliation-report.json`, `quality-gate-result.json` |
| report | all prior artifacts | `artifacts/*.xlsx`, `artifact-manifest.json`, `result-summary.json`, `run-manifest.json`, `reconciliation-report.json`, `unknown-types.json` |

## Serialization Notes

- `Decimal` values are serialized to strings in JSON.
- Normalized row data is stored in SQLite, with money fields stored as exact text.
- Paths are stored as private local/container paths and are not sent through n8n as row data.
- The final report still has 14 sheets generated by `src.report.generate_report`.

## Adapter State Audit

- Run-directory orchestration state is the truth source:
  - `<output_root>/.orchestration/<run_id>/run.json`
  - `<output_root>/.orchestration/<run_id>/stages/<stage>.json`
- `.pipeline-state` contains only rebuildable lookup pointers.
- Adapter stage execution calls the Python stage service functions; it no longer calls `pipeline_service.run_request()` for `reconcile`.

## Concurrency

- Each `run_id + stage` uses a lock file under `.orchestration/<run_id>/locks/<stage>.lock`.
- A concurrent request receives `STAGE_ALREADY_RUNNING`.
- Completed terminal stages return existing stage results without recalculation.

## OpenAPI

- Main API path is `/api/v1/...`.
- Legacy paths remain available and are marked deprecated in OpenAPI.
- `docs/n8n-migration/openapi.json` is generated by `python -m scripts.generate_openapi`.
- `tests/test_openapi_snapshot.py` enforces snapshot consistency and non-empty success schemas.

## n8n Workflow Audit

- Sub-workflows call HTTP Request nodes against `/api/v1/runs/{run_id}/stages/{stage}`.
- `retryOnFail=false` is preserved.
- Timeout is centralized through `PIPELINE_HTTP_TIMEOUT_MS`.
- FIN-00 has a gate after each stage and routes failures directly to FIN-90.

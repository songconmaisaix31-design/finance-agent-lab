# Phase 3 Acceptance Report

Version: `v0.3-n8n-mvp`

Acceptance date: 2026-06-30.

## Verdict

Phase 3 code-level stage extraction, API contract governance, run-state truth source, locking, index rebuild, Docker API 300k synthetic validation, and n8n visual MVP workflow cleanup are implemented and tested.

Manual browser execution is the official MVP path. Because login is user-owned, the remaining UI evidence must be captured by the user following `MANUAL_UI_ACCEPTANCE.md`. n8n API keys and `/rest/workflows` are not required for MVP acceptance.

## What Changed

- `pipeline_service.run_request()` now preserves its public signature but sequentially calls five real stage service functions.
- `pipeline_adapter` no longer calls full `run_request()` from `reconcile`.
- Normalized detail rows are stored in SQLite at `normalized-data/normalized.sqlite`; Decimal money values are stored as exact strings.
- Report generation is isolated to `run_report_stage()`.
- Run orchestration truth source moved to `<output_root>/.orchestration/<run_id>/run.json` and `stages/*.json`.
- `.pipeline-state` is rebuildable with `python -m src.cli rebuild-run-index`.
- Stage locking returns `STAGE_ALREADY_RUNNING` for concurrent same-stage requests.
- API canonical paths are `/api/v1/...`; legacy paths are deprecated but still available.
- OpenAPI snapshot is generated by `python -m scripts.generate_openapi` and tested.
- FIN-00 Master now has `Run Parameters`, per-stage gates, `Run Summary`, and a single right-side `FIN-90 Error` branch.
- FIN-90 Error now emits a fixed safe `Error Summary`.
- n8n no longer mounts `/finance-data`; data access stays behind the Finance Pipeline API.
- Workflow export now writes to a temp directory, copies back to an ignored local export folder, and sanitizes before updating templates.
- The local ignored n8n encryption key was rotated and the persistent n8n config was updated to match it.
